## ChatAgent 与完整 RAG 检索流程未统一

状态：已完成核心整改（2026-10-20，用户授权后实施）。

整改前发现：
- `search_rag`、`ask_rag` 和召回测试使用 `retrieve_knowledge()`。
- ChatAgent 的 RAG 工具及 `EvidenceStore.search()` 直接使用 `search_similar_documents()`。
- 因此聊天检索没有复用完整的仓库检索配置、配置的 Qwen 重排、父级扩展、分数阈值和 `answer_gate`。
- 底层仍有召回、融合、去重、同父块数量限制、可选本地规则重排和压缩，不能说完全没有质量处理。

本次对应的整改目标：
- 统一供正式问答、ChatAgent 和召回测试使用的检索能力与 trace，使配置实际影响聊天检索。
- 在 Agent 中复用重排、父级扩展和质量控制；探索阶段的过滤策略需要明确设计，避免机械套用固定问答阈值。
- 单次检索的 `answer_gate` 结果应作为继续检索、读取其他资料或澄清的信号，不应直接终止整个 Agent。
- 最终回答前综合文档、代码和结构化工具结果判断证据是否充分。
- 整改时重新核对实现，并验证聊天、RAG 问答与测试入口的行为一致性。

## 已整改：前端多个开发实例覆盖编译缓存（2026-10-20）

- 原因：同一项目曾同时在 3000、3001 运行 Next.js，两个进程共用 `.next-dev`，导致页面和框架错误组件的编译产物不一致。此前只重启和验证了 3000，遗漏了旧实例。
- 处理：在 Next 配置入口增加项目级启动锁；重复启动在写缓存前失败。锁同时记录 CLI 和服务工作进程，避免孤立子进程仍在运行时误清缓存。新实例获得锁后重建开发缓存，生产 `.next` 和项目数据保留。
- 验证：加入运行保护回归测试，覆盖重复启动、缓存保护、强制结束后的恢复、孤立子进程和构建目录隔离；实际验证全部页面、知识库详情、刷新与导航，并验证生产构建期间开发服务可继续访问。
