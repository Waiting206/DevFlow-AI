## ChatAgent 与完整 RAG 检索流程未统一

状态：已完成核心整改（2026-10-20，用户授权后实施）。

整改前发现：
- `search_rag`、`ask_rag` 和召回测试使用 `retrieve_knowledge()`。
- ChatAgent 的 RAG 工具及 `EvidenceStore.search()` 直接使用 `search_similar_documents()`。
- 因此聊天检索没有复用完整的仓库检索配置、配置的 Qwen 重排、父级扩展、分数阈值和 `answer_gate`。
- 底层仍有召回、融合、去重、同父块数量限制、可选本地规则重排和压缩，不能说完全没有质量处理。

本次对应的整改目标：
- 统一供正式问答、ChatAgent 和召回测试使用的检索能力与 trace，使配置实际影响聊天检索。
- 在 Agent 中复用重排、父级扩展和质量控制；探索阶段的过滤策略需要明确设计，避免机械套用固定问答阈值。
- 单次检索的 `answer_gate` 结果应作为继续检索、读取其他资料或澄清的信号，不应直接终止整个 Agent。
- 最终回答前综合文档、代码和结构化工具结果判断证据是否充分。
- 整改时重新核对实现，并验证聊天、RAG 问答与测试入口的行为一致性。

## 已整改：前端多个开发实例覆盖编译缓存（2026-10-20）

- 原因：同一项目曾同时在 3000、3001 运行 Next.js，两个进程共用 `.next-dev`，导致页面和框架错误组件的编译产物不一致。此前只重启和验证了 3000，遗漏了旧实例。
- 处理：在 Next 配置入口增加项目级启动锁；重复启动在写缓存前失败。锁同时记录 CLI 和服务工作进程，避免孤立子进程仍在运行时误清缓存。新实例获得锁后重建开发缓存，生产 `.next` 和项目数据保留。
- 验证：加入运行保护回归测试，覆盖重复启动、缓存保护、强制结束后的恢复、孤立子进程和构建目录隔离；实际验证全部页面、知识库详情、刷新与导航，并验证生产构建期间开发服务可继续访问。

## Agent 对比实验室：基础首版

记录日期：2026-10-21。

状态：待处理。用户当前仅要求记录；实施时再核对范围，不提前修改业务代码。

### 目标与使用流程

在独立实验界面使用同一问题、上下文和固定数据，对比基线 A 与候选 B 的回答、工具调用过程及消耗，帮助验证提示词或模型配置调整是否有效。

1. 前端从基线 A 复制创建候选 B，选择修改提示词、后端已配置的模型及该模型支持的参数。
2. 后端校验并保存候选配置，返回版本 ID；版本可重复使用，尚不改变日常聊天配置。
3. 用户选择实验用例、固定数据、A/B 版本和验收条件，手动发起对比。
4. 后端为 A、B 分别创建独立 ChatAgent 对象和执行任务，从任务起点运行并保存结果；通常不需要启动两套后端服务。
5. 前端展示运行状态、双栏工具轨迹、回答和验收结果，支持查看首次路径分歧及各步详情。

### 首版范围

- 只比较提示词、模型及受支持参数的配置版本。固定并记录 Agent 代码、工具集、Skill 版本/指令摘要和检索配置，避免其他变量混入比较。
- 实验参数通过运行实例注入，不修改全局 settings、正常聊天的模型对象或默认配置；基础首版不自动发布候选版本。
- 复用现有 Evals 页面、ChatAgent、trace 和评测基础，新增“Agent 对比实验”标签页或独立详情页；日常聊天继续单版本、单次生成，不默认双跑或展示新旧对照。
- 聊天消息菜单可增加“创建对比实验”，将问题和相关上下文带入实验。旧聊天没有完整录制数据时，只能作为新实验的题目来源，不标记为严格复现当时现场。
- 首版工具限定为只读且可隔离的工具，支持固定代码快照读取和已录制工具响应；执行路径不同导致的新请求，不能随意复用不匹配的旧响应。
- 对未录制且无法在固定环境执行的工具请求，显式标记回放缺失/实验不完整，不悄悄访问实时环境，也不将其混作可比的完整结果。
- 实验使用独立记录和隔离上下文，不污染正常聊天消息、长期记忆及正式业务记录，不执行 GitHub 写入或任意命令。
- 不纳入首版：任意历史后端代码版本并行运行、任意节点续跑、完整知识库/向量索引快照、无限制的新查询回放、自动修改生产默认版本。

### 后端实施要点

- 增加版本、实验用例、实验任务/运行及对比结果的持久化结构，区分“版本配置”“临时运行实例”和“对比实验”。
- 提供可用模型与参数能力查询、候选版本创建/读取、实验提交、运行状态和结果查询等接口。此处仅约定接口职责，具体路径实施时确定。
- 在工具结果被摘要压缩之前增加录制入口，保存脱敏后的完整输入输出、错误、耗时、工具标识及规范化参数；现有简略 trace 继续用于聊天展示。
- 固定并保存实际输入上下文、提示词内容/摘要、模型参数、代码快照标识、工具/Skill 信息和检索设置；快照不足时明确比较条件不完整。
- 在工具调用边界增加实验适配器，根据工具与规范化参数返回录制结果，或在独立只读快照上执行受支持的查询。
- 后台执行 A/B 任务，持久化 queued/running/completed/failed 等状态；首版进程重启后将遗留任务标记为中断并允许重跑，不承诺断点恢复。
- 比较最终任务验收、必要工具覆盖、重复调用和首次路径分歧；路径不同、工具更多或更少不直接等于质量更好。
- Token 区分模型实际返回值与估算值；耗时标明录制/回放模式，不将固定响应的执行耗时冒充真实线上工具性能。

### 前端展示

- 实验列表：用例、A/B 版本、创建时间、执行状态和验收摘要。
- 创建实验：问题/上下文、基线 A、可编辑候选 B、固定数据说明、验收条件和运行按钮。
- 结果详情：上方展示版本与数据条件，中间双栏展示步骤、工具和回答，下方展示验收与消耗对比。
- 步骤可展开查看参数、完整工具结果、错误与检索来源，并高亮首次路径分歧。
- 明确区分运行失败、回放数据缺失、验收未通过和正常完成；避免只给一个没有依据的“B 更好”结论。

### 验收标准

- 不改全局配置、不重启后端即可创建 B 并运行配置对比，正常聊天仍使用原默认配置。
- A/B 并发或顺序运行均不串用状态、参数、上下文、临时文件或业务写入。
- 相同固定条件下能查看完整工具轨迹与回答差异，实验条件不一致或录制缺失时明确提示。
- 可以复用保存的版本与用例再次实验，后台任务状态和已完成结果刷新后可查询。
- 验证未配置模型、无效参数、工具超时、回放缺失、任务中断和实验隔离等边界。
- 正常聊天、流式响应、历史消息、RAG 与现有评测链路回归通过；涉及模型随机性的质量结论使用多次运行，不能仅凭一次对比宣称改进。

工程量粗估：熟悉项目的单人全职开发，基础可用版约 10～15 个工作日；实际以实施前核对的工具范围、快照方案和界面细节为准。
